# AppleNotesPro：模型连接、场景 Agent 与 Skill 规划

> 2026-10-11修订：用户要求Agent仅用一份角色Prompt定义，搭配Skill；MCP／Tools暂缓。0.6.3已实现该简化。本文多字段角色表是历史方案，当前用法以[Prompt + Skill](AGENT-PROMPT-SKILL-0.6.3.md)为准。

> 2026-10-10：第一阶段已实现为0.6.0，具体交付与边界见[实现记录](AGENT-ROLES-0.6.0.md)。以下保留原规划，不能将后续项目当作已交付。

日期：2026-10-09。状态：产品与实现方案，供讨论；本轮仅整理规划和术语，未修改0.4.2应用。

用户目标：模型连接与提示词拆开；提示词和Skill统一管理，页面直接叫“Skill”；通过Agent角色，为公众号、个人笔记、汇报文档提供不同目标、判断视角和表达方式。日常操作继续在Notes旁的原生浮层完成。

## 1. 当前实现核对

- `SettingsView.swift`的“AI与提示词”同时容纳模型连接及提示词；另有“写作Skills”入口。
- `AIConfiguration`只有一份全局`systemPrompt`和`writingPreferences`，以及快捷动作`prompts`，没有场景角色。
- `InlineAssistantModel`与`WritingSessionModel`各自拼接全局说明和偏好；当前前者不加载Skill，后者通过`WritingAgent`加载任务快照中的Skill。
- `WritingDraft`保存批注、候选历史和Skill快照，但没有角色及角色版本快照。
- `WritingSkill.id`当前使用内容指纹。若角色长期引用Skill，后续需要区分稳定身份与内容版本，避免更新包后角色引用失效。

所以只改菜单名称或多放三条“你是某某专家”的提示词，不能完成场景切换。快捷AI与批注修订需要共享角色配置和指令组装逻辑。

## 2. 产品结构

建议AI相关设置只保留三个入口：

| 入口 | 管什么 | 用户日常怎么用 |
|---|---|---|
| 模型连接 | 服务地址、协议、模型ID、API Key、连接测试、默认连接 | 配置一次；通常不随文稿场景反复更换 |
| Agent | 面向谁、写作目的、判断视角、表达风格、质量标准、绑定的能力与常用动作 | 在Notes的AI面板直接选择角色 |
| Skill | 简单指令、标准Skill包、来源与版本、适用动作、被哪些Agent引用 | 配好后由角色使用，必要时临时调整 |

“通用、编辑工具条、模板、快捷键、关于”继续承担原来的配置职责。AI设置里的名称统一为“Skill”，不叫“写作Skill”。

提示词与Skill适合放进同一能力库，但保留类型：简单指令适合一个明确动作；Skill包适合一套方法及配套资料。标准Skill使用`SKILL.md`，也可附带资源；执行能力取决于宿主。本应用继续只支持现有指令与文本资源能力，不因改名开放脚本。[Agent Skills概览](https://agentskills.io/home)、[格式规范](https://agentskills.io/specification)。

每段现有提示词按用途迁移：角色说明进入Agent；任务指令进入Skill库的“简单指令”；用户临时要求仍留在当前修订会话。笔记模板继续作为插入内容的独立功能。

## 3. Agent与风格的区分

Agent回答“为谁、为了什么、按什么标准判断好坏”。风格回答“用什么语气、写多长、怎样组织”。

一个公众号编辑可以采用克制分析、观点表达等风格；一个汇报顾问可以给管理层写摘要，也可以给项目负责人写详细进展。不要为每种语气创建独立Agent。需要显著改变目标读者或评价标准时，再复制角色配置。

第一版提供三种可复制和修改的预设：

| Agent | 目标与读者 | 组织与判断标准 | 不应出现的行为 |
|---|---|---|---|
| 公众号编辑 | 面向用户指定的目标读者；先让人理解为什么值得读，再讲清观点与依据 | 从读者的问题和已有认知组织内容，解释必要术语，衔接自然，保留作者立场 | 编造故事、数据、引语；未经要求加入标题党、营销口号或行动号召 |
| 笔记助手 | 面向现在和将来的自己；帮助理解、回顾和继续思考 | 保留核心概念、机制、例子和未决问题，必要时整理层次，区分原记录与新增推断 | 把推测写成事实；抹去“我还不确定”；把所有笔记套成正式文章 |
| 汇报顾问 | 默认面向管理者或项目负责人，可修改目标读者；帮助理解进展和作出决策 | 在材料允许时连接目标、结果、影响、风险和待决策事项；结论先行，突出优先级和指标口径 | 用大词替代信息；虚构收益、风险评级、完成率、负责人、时间或战略目标 |

“从大局汇报”应体现已有材料与目标、影响、风险之间的关系。缺少业务目标、风险或决策信息时，标记待补充或保留为明确建议，不自动补成事实。没有足够材料支撑汇报结构时，不强行填满所有栏目。

“更加可读”也因读者不同而不同：公众号降低陌生读者的理解门槛；个人笔记便于自己重新找回思路；汇报降低决策者筛选信息的成本。

## 4. 相同材料的三种表现

以下只是产品示例，用于说明取舍，不是实际模型评测结果。

原始材料：单次处理时间从30分钟缩短到10分钟，仍需人工复核。

- 公众号编辑：过去处理一次需要30分钟，现在缩短到10分钟。不过，结果仍需人工复核，节省处理时间不等于完全替代人工。
- 笔记助手：处理时间：30分钟→10分钟。边界：仍需人工复核。待确认：复核环节还需要多长时间？
- 汇报顾问：进展：单次处理时间由30分钟缩短至10分钟。当前边界：仍需人工复核。后续建议：评估复核耗时，以判断端到端效率改善。

三者保留相同事实。第二个增加的是标明的待确认问题，第三个增加的是标明的建议，都不能冒充原始记录。

## 5. Agent配置与日常交互

最新交互补充：用户希望以原文为主，直接添加小气泡批注，最终在编辑区域右下角汇总整体意见并统一优化。局部气泡只保存对应原句的要求，保存时不调用模型；右下角提交时，把所选Agent、所有启用批注和整体要求一起交给修订内核。整体意见区随笔记编辑区域定位，不固定在整个桌面的右下角，也不常驻左右两栏。

右下角的紧凑区域建议包含Agent选择、已保存批注数量、整体意见输入框和“统一优化”。详细模型与Skill配置仍在设置维护。生成结果先预览，再由用户应用，添加意见本身不改正文。

用户已明确：“原文”指Apple Notes本身的正文，不再打开独立修订界面。0.5.0已增加附着Notes正文的批注气泡和右下角整体意见面板；Agent角色与设置拆分仍是本文规划，尚未混同为已交付功能。

Agent基础页提供：名称、目标读者、主要目的、判断视角、语气与篇幅偏好、输出组织偏好、启用能力、常用快捷动作。预设填好可直接使用；高级区域才放补充规则和示例，不要求用户先维护复杂提示词。

默认使用全局模型连接。可以在高级配置提供明确的连接覆盖选项，但第一阶段可不做；角色切换本身不静默切换模型、账号或服务地址。

Notes内的AI浮层和批注修订窗口，在主要位置显示“Agent：个人笔记”等角色选择。模型选择放到次级选项。用户可直接切换角色，继续选句、写批注、统一优化；不打开设置工作台。角色摘要和本轮启用能力按需展开，避免占用正文空间。

角色记忆：保存用户为该修订会话显式选择的角色；新会话使用用户设定的默认角色。首版不根据标题或正文静默猜测角色，不引入后台笔记分类、知识库或检索索引。

同一会话一次使用一个Agent。角色切换保留当前候选、批注和历史；下一轮用新的角色，当前运行不被后台配置编辑改变。此前角色的风格要求标记为历史上下文，不能继续覆盖新角色；此前用户明确提出的事实和批注意见仍保留。

## 6. Skill如何和Agent组合

Skill库区分“已安装/可用”与“本角色使用”。安装一个Skill不代表每次都向模型加载它。

Agent引用可复用能力，不复制出多份同名内容。例如Humanizer-zh可以同时被公众号编辑和笔记助手引用；汇报顾问也可以使用其中的去空话规则，但专业术语、指标口径及简洁结论应服从汇报目标。

能力还需要说明适用操作：润色、解释、摘要、翻译、批注修订等。第一版用明确的绑定与适用范围，避免依赖模型随意决定加载全部能力。简单指令可作为快捷动作；复杂Skill不一定是一个按钮。

尤其是“纠错”：即使选了公众号编辑，也不能擅自扩写开头或改变结构。动作决定允许修改的范围，角色只在该范围内发挥作用。翻译同样不能因为角色偏好额外增加营销段落。

建议预设能力侧重：公众号使用去空话、读者视角审阅；笔记使用结构梳理、术语解释、区分事实与疑问；汇报使用结论组织、指标口径检查、风险和待决策事项提炼。后几项是待实现的产品能力建议，不声称当前已经安装了这些外部Skill。

## 7. 指令与批注冲突

应用固有的读写保护、作用范围和支持能力始终有效。角色或Skill不能自行扩大Notes读取范围、执行脚本或直接写回正文。

响应协议也由宿主固定：快捷正文与修订JSON分别遵守所在流程的格式。迁移提示词中的“只输出正文”只约束文稿内容，不能覆盖修订流程所需的结构化结果、批注ID和处理说明。

内容层按以下规则处理：

1. 本轮整体要求、明确事实更正和局部批注优先；本轮新增要求只有明确替代旧要求时才覆盖旧要求。
2. 快捷动作约束允许进行哪些修改；例如纠错不升级成全文改写。
3. 场景Agent定义读者、目标、评价标准和默认风格。
4. 本轮启用的Skill提供实现方法；其通用偏好不能改写角色目标。
5. 公共偏好只提供未被前述规则指定的默认值。

局部批注“这一句保持原样”应约束该句；整体“更口语化”作用于其他可修改部分。若同一句同时被明确要求保持原样和改成另一种含义，又无法判断哪个要求更新，保留冲突并报告，不能随机取舍。角色切换不应静默撤销用户批注。

事实保留允许用户明确更正错误事实，例如把“无需人工”更正为“仍需人工复核”；Agent或Skill不能自行编造更正依据。

## 8. 实现方案

共用一个执行内核，用角色配置驱动行为；不为三个场景复制三套模型请求或修订循环。

- 新增`AgentProfile`：稳定ID、名称、读者、目的、视角、风格、质量标准、能力引用、常用动作引用、配置版本。第一版不保存密钥。
- 能力库保留两种类型：`PromptAction`简单指令与Skill包。为包增加稳定安装ID，内容指纹仅表示版本；角色引用稳定ID，每次运行固定内容快照。
- 新增共享的`AgentContextBuilder`模块：解析当前Agent和适用能力，处理默认值，构建同一轮使用的角色/能力快照；快捷AI与批注修订从同一Interface取得上下文。
- 批注修订仍执行分析、改写、复核及有界修正。复核既检查每条意见，也检查本角色的质量标准；输出要能说明未解决冲突，不能只宣称语气更专业。
- 快捷AI维持快捷执行体验，不必为了一个纠错动作强制执行完整多轮流程；但必须遵守同一角色、能力适用范围和优先规则。
- 只需指令的快捷能力可以保持单轮；依赖配套资料的Skill由共享加载器补齐所需资料，无法直接确定资料时交给有界Agent读取。不能只传Skill名称就宣称已应用，也不能静默忽略资料依赖。
- 每次候选历史记录使用的Agent名称/版本、能力指纹与操作类型。恢复旧稿时不猜测当时使用的角色。
- 读取角色、组装能力发生在进入会话或用户发起请求时，不进入Notes的按键与选区监听路径。

现有Skill资源能力边界保持。首版无需多Agent并行评审、自动路由、远程Skill市场或独立知识库。

## 9. 旧配置迁移

先备份配置和草稿，再做带版本的迁移；保留原文件，迁移失败不得覆盖或静默重置。

| 现有内容 | 迁移目标 |
|---|---|
| 模型连接、默认连接、Keychain引用 | 模型连接，原样沿用 |
| 用户当前systemPrompt与writingPreferences | “默认助手（原配置）”的说明与偏好，保持原行为 |
| 已有PromptAction及ID | Skill库的简单指令，保留名称、内容和引用 |
| 当前启用Skill | 绑定给迁移后的默认助手；不强制绑定给所有新角色 |
| 旧修订草稿中的Skill快照和批注 | 原样保留；缺少角色时恢复为迁移后的默认助手 |
| “AI与提示词”“写作Skills”的上次选中页 | 映射到新的模型连接/Skill页面 |

新用户直接得到三个场景预设；升级用户同时保留自己的默认助手，并可选择三个新增预设。内置预设更新不覆盖用户修改后的角色。

## 10. 交付顺序与验收

第一阶段作为一个完整版本交付：设置拆分和改名；统一能力库；三个场景Agent；原生浮层切换；两个AI入口共用角色；配置与旧草稿迁移。不能只做三个角色按钮而仍调用同一全局提示词。

后续再考虑角色导入导出、个人示例、更多可组合能力及用户主动发起的多视角比较。自动场景识别不作为第一阶段依赖。

验收用同一材料对照三种角色，不以“听起来像”作为唯一判据：

| 验收情形 | 预期 |
|---|---|
| 相同事实，切换三个Agent | 事实、数字相同；读者、结构与侧重点符合对应标准 |
| 三种角色均执行纠错 | 不新增段落、观点或营销话术 |
| 个人笔记包含“尚不确定” | 保留不确定性，不替作者作出结论 |
| 汇报缺业务目标和收益数据 | 不编造目标、金额、完成率；明确缺口或建议 |
| 公众号材料没有故事案例 | 不编造个人经历、采访或引语 |
| 多处批注与角色风格冲突 | 事实和明确局部要求保留；无法消解的冲突可见 |
| 后续轮次切换Agent | 保留候选和批注，新角色生效，旧角色风格不持续压制 |
| 运行期间编辑角色/更新Skill | 当前轮快照不变，后续轮显式使用更新 |
| 更新/删除被角色引用的Skill | 引用不会错绑；缺失能力明确可见，旧快照仍可恢复 |
| 旧配置与草稿升级/失败回滚 | 不丢提示词、密钥引用、批注或候选历史 |
