# 核心功能验收：从“有实现”到“能交付”

> 当前状态更新（0.3.5）：固定本机开发签名已生效；主要原生编辑、AI、模板和正文反链闭环已实测。旧版本权限阻塞与待验文字仅为历史记录。当前结果与未覆盖边界统一见 [0.3.5 实机验收](NATIVE-ACCEPTANCE-0.3.5.md) 和 [验证记录](../VERIFICATION.md)。

2026-10-08，基于当前 0.3.1。产品边界见 [当前功能](CURRENT-FEATURES.md)，完整取舍见 [ProNotes 最新对标](PRONOTES-CURRENT-PARITY.md)。本表只安排当前核心，不把已经移出的搜索/知识库或延期的文件导入导出列为完成条件。

## 通过标准

“代码已接通”“单元测试通过”“原生视图能渲染”“系统菜单动作已投递”均不能单独等于功能可交付。涉及编辑的核心操作必须满足：正确目标、正确结果、其他内容保留、失败可解释、必要时可撤销。模型质量与编辑机制分开验证；先用本地合成服务验证交互，不发送真实资料。

## 先解除的实机阻碍

用户已明确允许 OpenNotes 的辅助功能授权。当前系统辅助功能页中的 OpenNotes 开关为关闭，尝试开启再次出现管理员密码验证；应用仍显示未授权。需要用户在 macOS 原生认证窗口完成验证，聊天中无需提供密码。没有再次索取同一权限的授权，也没有绕过认证或直接修改 TCC 数据库。

此前完全磁盘访问列表的开关与 App 实际状态不一致，当前 App 仍显示需要授权。AI 局部编辑验收先处理辅助功能与已授权的 Notes 自动化；反链的数据库读取另行核实，不能将系统列表开关当作生效证据。

## 验收顺序

## 本轮实现修复与仍需实测的边界

- 0.3.1 已移除键盘 buffer 驱动的 Markdown 检测，改为真实正文/光标及输入前后匹配。
- AI/模板与反链写回统一到 Notes 原生粘贴，并补剪贴板版本保护和 UTF-16 字符边界检查；真实撤销行为仍需验收。
- 只在已识别的正文上读取全文；表格单元格必须明确选中文字，未知编辑器拒绝操作。
- 输入法组合状态不明确时不消费候选确认/导航键；可以点选 slash 菜单，真实中文输入仍需验收。
- 本地包为 ad-hoc 签名，更新后授权有效性需要实际检查；不能承诺免授权更新。
- AI/模板仍是纯文本，复杂表格内部反链与跨版本 schema 保持已披露的覆盖边界。

详见 [0.3.1实现记录](CORE-IMPLEMENTATION-0.3.1.md)。

该脚本已经进行实际 HTTP 流式自测，但尚未通过 OpenNotes 原位 UI 完成整条流程。真实模型 key、真实用户正文不属于这个测试。
