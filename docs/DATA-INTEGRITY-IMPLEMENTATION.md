## 反链读取的证据边界

生产反链服务现在从一个 SQLite 只读事务取得笔记元数据、正文和链接附件记录。SQL prepare/step/schema 错误会上抛；服务区分 idle、loading、ready、failed，面板另外区分当前目标尚未进入快照。只有成功提交当前 generation 的结果才更新成功时间，失败不会覆盖旧缓存或自动进入重试循环。

构建中收到强制刷新或失效请求时，合并为后续一次构建；旧 generation 不提交，等待回调在最终构建结束后统一触发。重复原生标识符的目标选择与图建立使用相同的确定性规则，避免图指向一个内部主键、查询却查另一个。

附件表残留行不能单独证明有反链。新路径同时检查正文属性中的链接、实际附件标记和对应源笔记。已删除附件、无正文标记的孤立附件不再生成幽灵反链。支持 `notes://showNote`、`applenotes://showNote`、`mobilenotes://showNote`、`applenotes:note/` 的有效 UUID；普通网页参数中的 Notes URL 不算原生链接。

密码保护笔记跳过；正文未同步/无法解码、链接元数据缺失、尚未解码的表格等复杂内容都产生覆盖范围信息。面板可以显示有效部分，并明确“结果可能不完整”。这种状态下的空结果显示“已读取内容中未发现反链”，不声称整个库没有反链。原生表格内部链接的完整支持仍是待完成项。

当前笔记解析也改用可抛错的数据库入口：要求原生标识符时明确失败；只需要当前 HTML 正文时，仍可使用有效 AppleScript 结果。旧兼容/研究读取方法仍存在，但生产反链和当前笔记解析已经不走吞错路径。

## 知识集合身份与 schema 2

显示名不再是检索过滤键。Notes 集合 ID 由数据库身份、账户关系和文件夹身份生成，不包含可变名称；同名文件夹不合并，重命名不改变集合。读取参考 NotesBridge 的 `ZOWNER`、`ZPARENT`、ICAccount/ICFolder 元数据，并考虑已观察的 `ZACCOUNT7`。

账户关系冲突或文件夹无法识别时，来源保持单独身份并显示待确认状态，不猜测账户后合并。嵌套路径用于显示；重复显示名增加短标识，便于在来源列表和选择器中对应。导入文件有独立集合 ID，不与名为“文件”的 Notes 文件夹相撞。

schema 1 → 2 在一个事务中只新增集合身份字段，保留 documents、chunks、FTS 与正文。旧 Notes 快照没有足够账户信息，按来源逐个隔离并标记待刷新；用户刷新 Notes 快照后取得真实账户/文件夹身份。旧文件来源保持在导入文件集合。迁移失败回滚列和版本，不删除原资料；未来版本索引仍拒绝降级打开。

选择的集合在刷新后消失或身份变化时，应用要求重新选择，不把选择自动改成“全部”。Notes 正文读取按用户选择的 UUID 分批绑定参数，不再逐条加载整库正文后才筛选。

## 实际执行的验证

- **WAL 一致性**：真实临时 SQLite 的第二连接在元数据与正文读取之间提交修改；当前快照仍同时看到旧元数据与旧链接，下一快照看到新状态。
- **反链范围**：孤立附件、删除标记、正文中的真实附件、无法解码/密码保护/复杂内容、普通 Web 重定向、重复元数据。
- **缓存状态**：失败不报零反链、不提前更新时间、不循环重试；失效构建丢弃；忙碌时刷新合并；回调等待最新结果。
- **集合与迁移**：两个同名账户文件夹检索隔离；账户/文件夹重命名 ID 稳定；嵌套路径、关系冲突；版本 1 正文/FTS 保留；迁移错误回滚。
- **当前笔记**：SQL 故障明确返回数据库不可用；合法的脚本正文读取不被不必要的原生 UUID 依赖阻断。

这些测试使用临时合成库和控制执行队列，不访问用户笔记。Mac 仍锁屏时，不能把它们当成真实库 schema、面板视觉、账户识别或 iCloud 同步已验收。原厂完整功能目标和其余数据/富文本缺口仍保留于 GOAL-STATUS.md。
