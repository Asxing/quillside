## 2. 可查的官网实现与版本管理

源码固定于 `6c1c0a7472f98a8ae197de84708530bd1a47ad31`，调研过程中仅下载公开文件到临时目录，没有复制到本项目或执行代码。

- 首页为 `site/public/index.html`，包含 HTML、样式与交互脚本，有深浅色适配、分享卡片元信息及产品图片；翻译由 `site/i18n.js` 管理。本轮核验的是这些入口，不推断不存在其他构建工具。[首页源码](https://github.com/yetone/magpie/blob/6c1c0a7472f98a8ae197de84708530bd1a47ad31/site/public/index.html)、[翻译源码](https://github.com/yetone/magpie/blob/6c1c0a7472f98a8ae197de84708530bd1a47ad31/site/i18n.js)
- Cloudflare Worker 配合静态资源和自定义域名；站点不只是展示页面，还承担稳定下载链接与更新元数据。[站点配置](https://github.com/yetone/magpie/blob/6c1c0a7472f98a8ae197de84708530bd1a47ad31/site/wrangler.jsonc)
- `/download` 默认映射 Apple Silicon，另有按系统/架构区分的路径，解析发布资产后跳转到 GitHub。`/api/latest` 返回版本、说明、地址、发布时间及资产信息，`/api/notes` 支持按版本范围取说明。更新缓存为 300 秒，源码包含 GitHub API 不可用时的回退处理。[Worker 源码](https://github.com/yetone/magpie/blob/6c1c0a7472f98a8ae197de84708530bd1a47ad31/site/worker.js)
- 直接读取在线 `/api/latest` 时，本轮 Python 请求收到 HTTP 403；浏览工具确认入口存在，但没有取得足够内容来验收实时版本或校验值。因此上述接口语义属于源码核验，不是线上接口全链路验收。

可借鉴的原则是让首页按钮、版本页与应用更新使用统一的发布记录。AppleNotesPro 目前仅 macOS 单平台，首发可在一个源码仓库中发布正式安装包，无需先复制双仓库调度、供应商合作、统计服务或复杂更新接口。

## 3. 我们的内容主线：在 Notes 内完成一次修改

以下是本项目的原创规划，依据当前 [README](../README.md)、[当前功能](CURRENT-FEATURES.md) 与 [0.6.3 实机验收](REAL-AGENT-SCENES-0.6.3.md)。借鉴展示方式，图片、视频、标题与叙述使用我们自己的内容。

建议一句话定位：**留在 Apple Notes，把想法写清楚。** 辅助说明可写：在原文中批注意见、切换写作角色、检查 AI 建议并写回笔记。正式品牌尚待确定；不能让访问者误以为产品由 Apple 官方提供。

| 首页位置 | 展示内容 | 要让用户理解什么 | 素材及约束 |
|---|---|---|---|
| 顶部导航 | 功能、快速上手、更新、GitHub、下载 | 去哪里使用、学习、反馈 | 入口少而明确；下载只有可实际安装的包上线后才启用 |
| 首屏 | 简短定位、两句说明、Mac 下载、在 Notes 中工作的真实画面 | 产品增强已有 Notes 写作流程 | Apple Silicon 与实际验证的系统范围明确显示；不承诺未经验证的全面兼容 |
| 主演示 | 选中原句 → 添加批注气泡 → 多处批注保留 → 右下角整体意见 → AI 候选预览 → 确认写回 | 用户如何闭环完成修改 | 以合成笔记录制约 20–30 秒实际操作；不能省略确认步骤伪装自动改写 |
| 原文批注 | 原句附近意见与整体意见放在同一画面 | 多条意见可以统一处理，笔记仍在 Notes | 展示保留、返回、检查；不承诺批注随 iCloud 在多设备同步 |
| 快捷 AI | 选区、润色或自定义要求、流式预览、替换/插入 | 日常小修改也方便 | 使用现有浮层；说明打开面板不会自动发送模型请求 |
| 原生编辑 | slash、Markdown 快捷格式、工具条、模板 | 不开 AI 也能改善写作操作 | 展示两三个高频动作即可，不把所有菜单铺成首页功能清单 |
| Agent / Prompt / Skill | 三场景切换；一份角色 Prompt 搭配 Skills | 用户能自行调整风格和方法 | 次演示用同一份素材切换公众号、个人笔记、汇报；结果应为实际生成并人工检查 |
| 正文反链 | 当前笔记查看来源、预览后写入原生链接、返回来源 | 现有笔记关系更容易回顾 | 明示主动更新；无需暗示后台扫描或自动全库同步 |
| 安全与上手 | 三步安装配置、权限用途、AI 数据流、支持入口 | 用户知道需要什么权限、会发送什么 | 与实际行为一致；详尽说明放文档 |
| 收尾与页脚 | 下载、源码、反馈、版本、隐私、许可、维护者联系方式 | 可以开始使用并获得支持 | 所有链接可访问，版本与实际资产一致 |

三场景展示要使用同一素材，以实际结果呈现差异：公众号帮助读者理解，个人笔记便于回看，汇报强调结果、证据与边界。一次受限素材的验收不能保证任意文章都有明显差异；演示应保留事实数字、条件和不确定性。

首页中不纳入暂缓能力：MCP / Tools、独立知识库、独立搜索、完整 Obsidian 文件导入导出、后台双向同步。基础 Markdown 复制也不能写成完整导出。

## 4. 官网、开源与发布需要共用什么

建议的职责分配：官网讲清用途并引导下载；用户文档帮助成功安装和完成第一次修改；GitHub 提供源码、许可、开发说明和反馈；Releases 存放可核验的正式版本、校验值与变更说明。

| 共用信息 | 官网 | GitHub / 文档 | 安装包与发布链路 |
|---|---|---|---|
| 产品定位与品牌 | 一句话及演示 | README 相同定位 | About、菜单、图标与发布者一致 |
| 版本与兼容性 | 下载按钮旁显示 | Release 说明写明已测与未测范围 | 版本、构建号、架构与实际产物相符 |
| 功能状态 | 只突出当前可用能力 | 已实现、限制、后续计划明确区分 | 未实现功能不提供无效按钮 |
| 数据流与权限 | 简短可理解说明 | 权限教程、隐私政策、撤销方法 | 首次使用与远程 AI 提示同一口径 |
| 问题反馈 | 可达的支持链接 | 缺陷模板与需求入口 | 说明如何提供脱敏诊断信息 |
| 开源范围 | MIT 与源码入口 | LICENSE、第三方说明、构建方法 | 打包保留必要许可，签名私钥不公开 |

本项目不必照搬 Magpie 的维护者独占提交策略。可选策略是接受 Issue 与经过审核的 Pull Request，首次优先欢迎文档、翻译和可复现缺陷报告；涉及 Notes 写回与权限的修改需要专门验收。最终协作规则应在公开仓库前确定。

运营先保证一个长期可维护的反馈入口。若采用 GitHub Issues，就把官网、应用与文档连接到同一入口；是否增加 Discussions、群聊或 Discord 取决于维护能力。赞助与合作位可后续增加，首发不需要先建立商业广告系统。可见的社区与赞助入口不等于已有成熟运营结果。

## 5. 首次对外展示前的材料和修复

我们可以准备：以合成 Notes 内容制作截图和短录屏、首页原创文案、三场景展示、上手/权限/模型配置文档、FAQ、版本说明格式、反馈模板与第三方许可整理。

必须避免的事实错配：`OnboardingView.swift` 中“所有处理都留在本机”与远程 AI 能力不符。官网与应用需共同说明：编辑增强及草稿本地保存；用户主动生成时，所选材料、指令及相应 Prompt / Skill 会发送到配置的模型服务；服务的保存政策由相应提供方决定。模型地址可以是本地或远程，不能把 BYOK 写成所有处理都本地。[当前 onboarding](../src/Quillside/App/OnboardingView.swift)、[当前行为说明](../README.md#权限与本地数据)

官网内容完成不等于正式包已准备好。Developer ID 签名、公证、真实下载后的 Gatekeeper、首次授权和升级保留配置仍属于独立发布验收。当前 README 明确包尚未 Developer ID 公证或公开发布。

需要用户最后确定的外部信息：正式品牌和发布者身份、域名及托管账号、GitHub 仓库归属、支持邮箱/反馈入口、首发免费或收费与是否坚持用户自行配置模型、首发语言及兼容范围。账号密码、签名私钥、API Key 不写入聊天、官网或公开仓库。

本轮交付是研究与内容方案，没有创建官网、改变应用代码、发布 GitHub 仓库或向外部服务写入内容。后续可先做可审阅的官网内容稿和演示脚本，再制作页面并接入已经通过发布验收的安装包。

以下是本机与仓库在 2026-10-12 的只读核查结果。功能验收和公开分发验收分别判断；本轮没有重新运行三场景模型测试。

| 工作 | 已有基础 | 对外发布前还差什么 | 责任与用户输入 |
|---|---|---|---|
| 产品材料 | 0.6.3 已有三场景、批注、写回与撤销验收记录 | 当前 README 大量内容按开发版本排列，功能清单夹杂历史状态；需形成面向新用户的介绍，历史证据保留在文档中 | 我们整理内容；用户确认主打场景和品牌 |
| 展示素材 | `docs/images/` 目前是 0.3.0 的三张旧界面截图 | 按当前版本重录原文批注主流程、三场景切换、快捷编辑；使用合成笔记，不拍摄个人笔记、模型密钥或账号 | 我们准备演示脚本和素材 |
| 正式签名 | 本地包可运行；已有构建、DMG、公证脚本 | 当前安装包是本机开发签名，未标记 hardened runtime、无 TeamIdentifier；尚不是 Developer ID 公证发布包。需检查签名、时间戳、公证结果、票据和下载后 Gatekeeper 行为 | 用户确认 Developer Program 会员和团队，在本机完成证书/公证认证；我们完善并验收流程 |
| 版本与升级 | `VERSION` 与本地 release JSON 有版本和校验值 | `CFBundleVersion` 当前固定为 1；需递增构建号、公开发布清单、旧版配置/Keychain/授权迁移测试。首发可手动更新，自动更新另作后续阶段 | 我们实现；用户提供稳定下载域名。不能承诺所有更新都不再触发系统授权 |
| 干净环境测试 | 当前实际验收机为 Apple Silicon / macOS 26.5.2；构建最低版本设置为 14.0 | 在无开发环境、无旧授权的普通用户机器验证安装、拒绝/恢复权限、Notes 写回与撤销、停止 AI、升级。最低构建版本不等于全部版本已测 | 我们整理和执行可用环境测试；用户提供其他测试机或首批测试者，确定首发支持范围 |
| 隐私与许可 | 已有数据流说明、MIT 和第三方 notices | 修正引导中的本机处理绝对表述，补对外隐私说明、权限指引和支持信息，核对打包许可；保留 NotesPlus 等实际使用代码的原始版权 | 我们整理；用户提供发布主体、联系邮箱及 AI 服务经营方式 |
| 源码与社区 | 本地源码和 source.zip 已有 | 本地 Git 无首个提交、无 remote；需清理公开范围、检查敏感材料、建立可复现构建说明、标签、Release 和反馈模板 | 用户提供 GitHub 归属/仓库名称及协作策略；我们准备可审阅内容后再发布 |
| 官网与下载 | 本文提供内容方案 | 需要页面、域名/HTTPS、下载资产、版本说明、快速上手、FAQ、隐私与支持入口；检查移动端、键盘操作、深浅色和链接 | 我们构建与验证；用户提供域名、托管归属和最终发布授权 |

官网分发适合继续保留现有 Notes 增强架构。正式分发按 Apple 的 [Developer ID 指引](https://developer.apple.com/developer-id/)完成签名与公证；公证是自动安全检查，不等于 App Store 审核。普通 App + DMG 路线使用 Developer ID Application，不必为此改成 PKG 或先取得 Developer ID Installer。

正式品牌需要单独确认。Apple 的[第三方商标使用指引](https://www.apple.com/legal/intellectual-property/guidelinesfor3rdparties.html)也适用于网站与产品命名；建议使用独立产品名，将“适用于 Apple Notes”放在兼容性描述中。此处是发布前命名建议，尚未改动当前 AppleNotesPro 名称或内部标识。若改名，应同时规划既有设置、Keychain 和系统授权的迁移。

推荐顺序：

1. **定内容。** 确认一句话定位、首页分段、主流程演示脚本、三场景示例和公开能力边界。此阶段不依赖开发者账号或域名。
2. **做可审阅页面。** 使用当前 App 的合成笔记素材完成本地官网预览，同时整理用户文档；GitHub 项目介绍待下一轮专门讨论后再写。
3. **补分发条件。** 正式签名公证、发布清单、干净机器安装及升级测试、隐私与权限说明一起完成。测试通过前，官网只用于预览，不把开发包包装成正式安装包。
4. **同步公开。** 同一版本发布源码标签、安装包、官网、文档和变更说明；让反馈归入一个长期维护的入口。首次可采用免费公开测试版、用户自配模型；收费与托管 AI 另作经营决策。

公开前用户需要确认的最小信息：**正式品牌/发布者、GitHub 归属、域名/托管归属、Developer Program 状态、首发免费或收费及模型由谁提供**。支持邮箱和首批测试者可以一起补充。对中国和海外用户的下载可达性需实测，网站部署地与实际 AI 服务形态涉及的适用要求应按最终经营方案核验。
