# Quillside 0.6.5：选区、批注与 AI 写回验收

2026-10-13，本机开发签名安装。只操作专用合成笔记“Quillside 1013 完整闭环验收”，没有修改用户的其他笔记。

## 发现的问题与修复

0.6.4 的整篇候选生成、原生写回和一次撤销均成功，但写回成功后 WritingSessionModel.apply 删除了草稿文件。随后即使在 Notes 撤销正文，也无法重新打开原来的批注。

0.6.5 保留写回前已落盘的原文、批注、角色/Skill快照及候选历史，只结束当前操作。恢复时仍检查笔记身份和原文基线；正文与基线不一致时保留旧草稿并阻止覆盖，不把旧偏移用于修改后的正文。用户明确选择重新开始时，现有归档流程仍保留上次草稿。

新增参数化回归覆盖“替换原文”和“插入后方”。旧代码两项均因草稿不存在而失败；修复后两项通过。

## 新版模型复验

0.6.5重新安装后需要macOS再次确认钥匙串访问。用户完成确认后，合成文本测试显示“生成与流式结束测试成功：OK”，随后重新完成整篇优化和单句优化，各自首次写回成功、一次撤销恢复原HTML。最后重开整篇批注，5条意见和最新候选仍在。

整篇使用“个人笔记”Agent与humanizer-zh；0.6.5单句入口使用原来的“默认助手（原配置）”。本轮没有重复公众号和汇报的风格对比，也没有量化真实鼠标拖选的延迟。四段候选与上轮文本相同，但有新的模型版本ID和5条处理说明，未把读取旧文件充当新生成。

## 自动化与证据边界

电脑控制工具初期能操作后台Notes窗口，但未保持Notes真实前台，工具条因此隐藏。用户将Notes置于前台后原位流程可操作；没有为自动化放宽前台、笔记身份或写回保护。一轮生成曾因离开原笔记自动停止，五条意见保留，恢复后完成真实生成。

两个按钮操作的电脑工具返回AX错误，但下一次观察已显示操作完成；均先读回状态，未重复发送模型请求或重复写回。一次批注气泡观察发生在异步呈现前，等待下一次界面观察确认引用后才填写。

修复复测前，仅从本轮验收证据恢复被旧版删除的合成测试草稿，随后在0.6.5实际执行写回、撤销和重开。该恢复动作与新版本的保存能力分开记录。

完整回归报告：252项测试、42个套件，3项因截图/实机数据库环境未启用而跳过；其余通过。参数化新增测试包含2个用例。release/debug构建、严格签名和随包MIT许可检查通过。8个非草稿配置文件哈希未变。

本地证据位于`build/native-loop-1013/`，包括原文HTML、写回/撤销读回、批注快照、候选截图、红绿回归日志。`python3 build/native-loop-1013/verify_evidence.py`核对实际材料。草稿中的Skill操作集合序列化顺序可能变化，历史比较仅对该集合排序，其余内容逐项比较。
