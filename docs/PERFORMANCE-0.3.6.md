# 0.3.6 输入性能重构与连接编辑修复

2026-10-09，macOS 26.5.2 arm64。以用户已确认基本正常的0.3.5为功能基线，优化普通输入路径和已有模型连接编辑，不增加产品功能范围。

## 输入卡顿的证据与改动

旧版 Slash 和 Markdown 各有100ms定时器，在主线程独立调用 NotesEditorContext.read，重复跨进程读取完整正文与祖先节点。选区工具条在光标移动时也先读取整篇正文；键盘event tap在部分普通字符事件中同步查询Notes，会延迟按键传递。

使用同一篇万字级合成笔记，Notes前台、光标位于正文，分别对已安装release进程采样8秒（2ms间隔）。采样记录只包含调用栈，不记录笔记正文：

| 指标 | 0.3.5 | 0.3.6 |
|---|---:|---:|
| 主线程定时器路径采样占比 | 69.29% | 0.56% |
| 主线程等待事件采样占比 | 30.45% | 99.23% |

这是墙钟调用栈占比，包含跨进程等待；不是CPU利用率，也不是用户按键延迟百分比。最终采样中仍能看到后台EditorInputObserver/NotesEditorFocus实际查询，未把失去Notes前台后不工作的状态当优化结果。

- 新增共享EditorInputObserver，监听现有AX通知和键盘通知；查询在后台串行队列运行。
- 普通输入只读取光标前最多192个UTF-16单元；仅检测到可能的Markdown/slash前缀才读取完整快照。空行和普通段落不需要整篇快照。
- 多次通知合并为一个执行中查询和一个待执行刷新，不让慢AX请求按键数积压。750ms轻量恢复探测兼容可能遗漏通知的辅助输入。
- 文本/焦点变化使候选缓存失效；执行编辑时仍完整校验窗口、选区、正文与目标，未用缓存直接写入。
- event tap不再同步访问Notes AX；仅使用最近候选快照决定命令导航，实际动作仍重新校验；普通按键立即返回。
- 工具条先判断焦点及非空选区，不读取整篇正文；选区查询也合并。笔记身份/反链被动刷新等待400ms输入停顿，减少连续打字期间的自动化调用。
- slash词法扫描限制到光标前129个UTF-16单元，避免长文前缀的全量拆分。

## 已有模型连接编辑

旧版已有编辑能力隐藏在看起来像链接的名称上，重新打开页面默认是空白“新连接”，没有明确编辑状态。新版页面自动载入默认或第一个已有连接；每行提供“编辑”按钮、当前项高亮，表单标题和按钮分别显示“编辑已有连接/保存修改”或“新建/保存新连接”。

ConnectionEditorState统一维护编辑ID与草稿。只有用户主动改协议时才适配默认URL，加载已有连接不触发URL重写。保存复用连接ID；API Key留空沿用原凭据。删除当前临时项或导入后正确选择剩余项。

实机用无密钥临时Ollama连接覆盖：保存fixture-before → 重启 → 编辑fixture-after和4096 tokens → 保存修改 → 再重启读回。连接数量未增加，删除临时项后原用户连接、默认ID、地址、模型、token上限和credentialID均与之前一致。回归测试还用合成钥匙串验证更新旧模型保留原密钥，保存失败不改旧配置。

## 回归与范围

192项测试中191项执行通过，1项旧宣传截图跳过；30套件。新增长文普通输入无全量读取判定、命令/分隔符识别、1000次事件风暴合并和取消过期结果、旧连接保存重启等回归。当前原生界面渲染和合成Notes数据库用例已开启。

实机：长笔记Slash /h1和/block、Markdown ##、/meeting日期、多行模板、选区工具条/下划线、AI打开均通过；连续输入200个数字精确读回。中文/emoji粘贴内容参与长文场景；不把CUA英文键盘输入当成物理中文输入法延迟测试。个别自动化动作发生在设置前台时已作废，恢复Notes前台后重测。

已安装0.3.6，固定本机开发证书继续有效，AX/FDA授权无需重置；历史AppleEvents记录差异沿用0.3.5披露，实际Notes自动化正常。未发送真实笔记给模型，没有修改用户原模型的密钥。临时模型连接已删除，合成性能笔记保留以便复测。
