# Pi 0.7.0 真实订阅与 Notes 验收

2026-10-13。最终安装Quillside 0.7.0构建3，Pi 1.2.0，内置官方Node v22.23.2。已完成真实账户授权及Notes单句、整篇闭环。

## 订阅路径

用户在OpenAI浏览器页面完成Quillside客户端授权。Pi保存openai provider的OAuth凭据，包含直接订阅调用所需scope；未把令牌或回调地址写入证据。原生设置显示“已授权订阅”，选择并保存OpenAI / ChatGPT · GPT-6.1 Sol后，固定文本测试收到OK及完整流结束。

本次走OpenAI官方Responses订阅路径，没有经过原来的本地Magpie网关。旧“本地”连接仍保留，默认模型已按本次订阅接入切换为openai/gpt-6.1-sol。Codex（兼容）、其他服务商目录和登录接口已实现，但未另用真实账户登录每个服务商。

## 原位工作流

仅操作已有合成测试笔记“Quillside 1013 完整闭环验收”。

- 单句：Notes浮条的“润色”经Pi生成新候选；首次替换只改变所选句，其余正文不变；一次⌘Z恢复原文和HTML格式。
- 整篇：恢复原有五条批注及“个人笔记”角色/humanizer-zh，点击统一优化，经Pi完成分析、修订和核对，产生新的候选版本；五个批注ID、原句和意见不变，每条都有处理说明，issues为空。
- 首次整篇写回与候选逐字一致，标题保留；一次⌘Z恢复原文及HTML。写回后批注草稿仍在，五条意见与新候选历史保留。
- 独立核对30分钟、10分钟、同类20次试用、三人口头反馈、未做正式问卷、人工复核及未知的复核耗时、负责人/时间未定等边界，未只依赖模型自评。
- 完成后没有Pi子进程残留；不保留远程会话或后台生成。

## 测试中遇到的边界

首次单文件包遗漏Pi的动态OAuth模块，导致登录在打开浏览器之前失败；通过Pi官方静态注册接口修复，并新增分发包测试后重新安装。用户在新流程中重新授权，成功保存并完成真实推理。

电脑自动化多次切换前台，导致原位面板按保护规则关闭或拒绝错误的编辑目标。没有绕过前台及正文身份检查，也没有盲目重试写回。后续把选区、打开面板和执行动作连续操作；整篇候选在暂时失焦后从本机草稿恢复，不重复生成。真正写回各点击一次，并独立读回。

源代码测试与安装包测试分开：8项Pi集成测试通过，261项原生测试中257项执行通过、4项条件跳过。最终OAuth修复使用已签名安装包独立验证，目录/登录不依赖开发机node_modules。
