# AppleNotesPro 产品范围

更新：2026-10-08。以本次用户讨论为准；此前全功能比较保留为研究记录，不再将所有上游功能视为交付要求。当前收敛实现见 [功能清单](CURRENT-FEATURES.md)；方案与实机验收仍分开记录。

## 已确认的定位与取舍

AppleNotesPro 是贴着 Apple Notes 编辑过程工作的原生 macOS 增强工具。笔记由 Apple Notes 管理；原文搜索使用 Notes 自带能力；跨笔记 AI 搜索与问答交给外部 MCP/AI 工作流。

| 范围 | 决定 |
|---|---|
| 编辑 | 保留选区格式工具条、Markdown 快捷输入、slash 命令、模板 |
| AI | Notes 内处理选区/当前笔记，原位预览与受保护写回；统一设置仅维护模型、API Key、提示词、写作偏好 |
| 反向链接 | 用户明确需要；优先考虑把可点击链接保存到 Notes 正文，减少对外部面板的依赖 |
| Markdown 交换 | 后续阶段：当前 Notes 导出至 Obsidian、Obsidian Markdown 插入当前 Notes；本轮不实施 |
| 移出 | 独立知识库、文件知识摄入、资料集合、快照管理、全文/语义检索、独立搜索窗口与搜索热键、跨笔记 AI 问答 |

不因为已经存在实现而保留被移出的产品功能。收敛代码时保留用户已有数据，不自动删除历史 knowledge.sqlite 或个人配置。模板列表内的名称筛选属于模板选择交互，不是重新建设笔记搜索。

## 正文反链：建议的产品行为

先区分两种操作：手工在 A 中添加指向 B 的链接，已有 Notes 原生入口；自动找出哪些笔记引用当前 B，并在 B 中生成返回链接，才是需要补齐的反链增强。

建议入口是“将反向链接写入当前笔记”与“更新正文反向链接”。例如 A《项目方案》引用 B《需求讨论》，在 B 的正文末尾生成“引用此笔记”区域，其中有可点击的 A 链接。保存成功后链接是 Notes 内容，打开它不依赖 AppleNotesPro 面板。iCloud 笔记可随 Notes 同步；具体系统/账户支持与链接形态仍须实机验证。

首个方案采用用户触发的更新。首次插入先预览来源，之后只更新可识别且未被用户改动的生成区域；其他正文保持。区域无法可靠识别、用户已编辑区域、写入目标变化时停止覆盖。读取不完整时合并新增来源并保留已有来源，预览明确提示。0.2.0 已补实现与回归，实际 App 完整写入流程尚待验收。

链接随正文保存不代表列表会自动保持最新。A 删除链接、来源移动/删除时，需要再次更新。后续如增加自动维护，必须单独设计更新时机。无需知识库或全文搜索，但发现反链仍需读取笔记间的链接关系。算法必须区分原始引用与自动生成的返回链接，避免把生成区域再次当作来源而反复增加条目；重复更新应产生相同结果。

## 后续阶段：Notes 与 Obsidian 的内容交换

系统能力和具体版本以 [原生能力核对](NATIVE-NOTES-MARKDOWN-RESEARCH.md) 为准。macOS 26 已有 Markdown 文件导入/导出；本产品重点补跨应用操作步骤和内容兼容，不把已有菜单包装当成全部增量。

建议的两个入口：

1. **导出当前笔记到 Obsidian。** 选择并记住用户指定的 Vault/子目录；生成 Markdown 与必要的本地附件；导出成功后可打开文件。保留回到源 Notes 的链接；重复导出需识别同一来源，目标已被编辑时明确展示差异或另存，不能静默覆盖。普通“导出 Markdown 文件”可复用同一管线。
2. **从 Markdown 插入当前笔记。** 选择 `.md` 文件，展示转换预览，插入已捕获的光标位置或追加到正文。内容应成为可编辑的 Notes 内容，不是把 `.md` 附件塞进正文；不默认替换整篇。笔记、光标或正文发生变化时停止应用并保留预览。

导入导出是一轮由用户触发的内容转移，当前不扩展为后台双向同步或全库迁移。

兼容性要求：

- 标题、段落、粗斜体、列表、任务项、代码、表格逐项验证，声明不能保真的格式。
- 图片/附件必须复制或嵌入可访问的内容并修复引用，不能把占位文字当成完整导出。
- Notes 内链：若目标也有导出映射，可转为 Vault 内链接；无映射则保留回到 Notes 的原始链接，不制造不存在的 Markdown 文件。
- Obsidian `[[双链]]` 与 `![[嵌入]]` 需要解析真实目标；有可靠 Notes 映射时转 Notes 链接，否则保留可打开 Obsidian 的链接或提示未转换。标题/块引用、同名笔记、相对路径与附件嵌入分别处理，不能只用字符串替换。
- YAML 属性、callout、插件语法的处理政策需在预览中清楚呈现；不声称两个格式体系完全等价。
- 当前系统原生支持可利用；项目原来的 macOS 14 最低版本仍在，旧版兼容方案尚未确定，不能把26的能力视为全版本可用。

## 当前代码与下一步

0.3.0 进一步收敛交互：所有 AI 入口接入 Notes 旁的非激活面板，不打开后台编辑器；模板与正文反链预览也采用就地面板。后台统一为配置窗口。会话状态测试与静态视图渲染通过，设置已实机检查；当前缺少辅助功能权限，Notes 内生成/写回尚待验收。

0.2.0 已移出独立搜索和知识库的界面、热键、索引与检索实现；历史源文件保存在 `legacy/retired-features/`。保留解码器用于反链。新增正文反链预览、受保护的富文本局部粘贴、区域所有权持久化与生成链接排除逻辑。用户的历史索引与配置不自动删除。

[NoteActionsService](../src/Quillside/Features/NoteActions/NoteActionsService.swift) 的原有 Markdown 复制继续保留；[转换器](../src/Quillside/Services/AppleNotesMarkdownConverter.swift) 的附件占位限制没有改变。导入导出按最新用户指示延期，不是本轮完成条件。

下一步聚焦当前核心的实机验收：正文反链写入/更新/撤销、工具条、模板、AI 局部写回、输入法与窗口切换。具体本轮结果和工具阻碍见 [验证记录](../VERIFICATION.md)。

## 2026-10-09 新增写作修订范围

用户已要求支持Skills和多处批注统一优化；0.4.0增加候选稿原生划线/评论、Notes选区加入意见、有限步骤写作Agent、版本历史和本机修订草稿。设置只维护模型/Skills/指令/模板，日常仍在Notes旁操作。完整知识库、独立搜索和文件交换的旧决定不变。实测范围见 [0.4.0实现](WRITING-AGENT-0.4.0.md)。


## 2026-10-09 原文气泡交互

用户明确要求在Apple Notes本身正文批注，不再打开独立修订界面。0.5.0提供Notes选区→原句气泡→编辑区右下角整体意见→统一优化→预览/应用，批注为本机覆盖层，不写入原文格式或同步评论对象。角色与设置重组仍见独立规划。验收见[NATIVE-ANNOTATIONS-0.5.0](NATIVE-ANNOTATIONS-0.5.0.md)。


## 2026-10-10 场景Agent

0.6.0完成模型连接、Agent、Skill设置拆分。公众号/个人笔记/汇报三个角色共用上下文构建，Notes快捷AI与原文批注直接切换；提示词与Skill包统一在Skill库配置。旧配置保留为默认助手，角色不改变模型连接。详见[0.6.0](AGENT-ROLES-0.6.0.md)。
