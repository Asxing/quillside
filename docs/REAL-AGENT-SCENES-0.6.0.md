# AppleNotesPro 0.6.0 三场景真实模型验收

2026-10-10。使用用户已授权的现有“本地 / codex/gpt-6.1-sol”连接，经OpenAI Responses协议调用真实模型。未使用模拟模型服务；模型连接、角色、Skill配置均保持原样。

## 结论

三个场景的五条批注、关键事实、最终写回和一次撤销均通过。风格区分未完全达到明显可辨的程度：汇报更正式并以阶段性结果开头，公众号和个人笔记在本例中仍比较接近。不能据此宣布三个角色的文风已经充分拉开。

汇报首次输出加入段间空白行，原生格式保护拒绝覆盖，原文未改变。追加仅去除空白行的要求后，真实模型返回文字完全相同、只调整换行的结果，之后写回和撤销通过。此案例不是三个角色首次写回全通过。

| 场景 | 批注与事实 | 风格观察 | 原生写回 / 撤销 |
|---|---|---|---|
| 公众号 | 5/5完整，关键事实与限制保留 | 自然段叙述，转折自然，去夸大；与个人笔记差异温和 | 首轮写回与一次撤销通过 |
| 个人笔记 | 5/5完整，明确数据只属整理阶段 | 边界和未知事项清楚，但结构仍接近普通文章，辨识度偏弱 | 首轮写回与一次撤销通过 |
| 汇报 | 5/5完整，无虚构收益/负责人/日期 | 阶段性结果先行，用语更客观正式 | 首轮因空行拒绝；格式修正后写回与一次撤销通过 |

## 测试方法

每个角色使用独立的合成Notes笔记，原文、五条批注、整体要求和Humanizer-zh快照相同。每个角色从原文开始，不沿用前一角色的候选。测试正文固定四段，限制了排版自由度；因此风格观察针对这一条件，不是所有写作题材的普遍质量结论。

通过Notes工具条逐处添加五条意见，实际选择对应Agent并执行分析、修订和复核。核对应用保存的草稿：五个批注ID、引用及意见未变，结果中每个ID出现且仅出现一次，均有处理说明。进一步独立阅读实际候选检查事实和风格；没有仅依赖模型自评的addressed状态。

每个最终候选均点击“应用到原文”，读取Notes实际正文，与预览逐字比较；检查标题未改，再按一次⌘Z，确认完整恢复原始正文。三篇验收笔记当前均已恢复原文，保留供复测。用户既有笔记没有纳入模型输入。

## 相同输入

这次我们对内部工单整理流程做了一个非常重大的优化。过去整理一份工单平均需要30分钟，现在平均需要10分钟。这个结果来自同一类工单的20次试用。
整理后的结果仍然需要同事逐项复核。我们还没有统计复核要花多少时间，所以目前还不能判断从接单到完成的总耗时下降了多少。
大家觉得新流程用起来可能更顺手，但这只是三位参与试用同事的口头反馈，没有做正式问卷。我们不确定其他类型的工单能不能得到同样的结果。
我们想下一步补记人工复核耗时，再试用另一类工单。暂时还没确定负责人和完成时间。

整体要求：按当前Agent的目标读者和质量标准优化全文，保留全部事实、数字、条件及五条批注。保持4个正文段落，不改标题；每条处理说明简洁。

五条批注：

1. **非常重大的优化**：去掉夸大判断，只描述试用观察，不写成已证明的全面提升。
2. **30分钟，现在平均需要10分钟**：保留30分钟、10分钟、同类工单20次试用；不要把整理阶段耗时当成端到端耗时。
3. **还没有统计复核要花多少时间**：必须保留复核耗时未统计、端到端改善尚不能判断；不能声称完全自动。
4. **三位参与试用同事的口头反馈**：保留三人口头反馈、未做正式问卷、其他工单效果未知；不要增加满意率或推广结论。
5. **暂时还没确定负责人和完成时间**：保留负责人和完成时间未定；下一步仍是计划，不得写成承诺或已经完成。

## 三个真实候选

### 公众号

```text
这次我们试用了调整后的内部工单整理流程。过去整理一份工单平均需要30分钟，在同一类工单的20次试用中，整理阶段平均需要10分钟。
整理后的结果仍需同事逐项复核。我们还没有统计复核耗时，因此目前尚不能判断从接单到完成的总耗时是否有所改善。
三位参与试用的同事在口头反馈中觉得，新流程用起来可能更顺手。不过，我们没有做正式问卷，也不确定其他类型的工单能否得到同样的结果。
我们想下一步补记人工复核耗时，再试用另一类工单。目前，负责人和完成时间还没有确定。
```

自然段叙述与转折说明，减少夸大和术语门槛；没有添加营销或虚构故事。

### 个人笔记

```text
这次我们调整了内部工单整理流程。在同一类工单的20次试用中，整理一份工单的平均耗时从过去的30分钟降到10分钟。这些数字只反映整理阶段的耗时。
整理后的结果仍需要同事逐项复核。我们还没有统计复核耗时，所以目前还不能判断从接单到完成的总耗时是否改善、下降了多少。
三位参与试用的同事觉得新流程用起来可能更顺手，但这只是口头反馈，我们没有做正式问卷。其他类型的工单能否得到同样的结果，目前还不确定。
我们想下一步补记人工复核耗时，再试用另一类工单。负责人和完成时间暂时还没确定。
```

明确注明数字仅属整理阶段，保留待确认项；与公众号版结构和措辞仍较接近，场景风格辨识度偏弱。

### 汇报

```text
内部工单整理流程调整后，同一类工单的20次试用显示，整理一份工单的平均耗时由过去的30分钟降至10分钟。这一观察仅涉及整理阶段。
整理后的结果仍需同事逐项复核。人工复核耗时尚未统计，因此目前还不能判断从接单到完成的端到端总耗时是否改善、下降了多少。
三位参与试用的同事口头反馈，新流程用起来可能更顺手。目前未做正式问卷，其他类型工单能否取得同样的效果也尚不确定。
我们计划下一步补记人工复核耗时，再试用另一类工单。负责人和完成时间暂未确定。
```

以同类20次试用和30→10分钟的阶段结果开头，使用客观、正式表述，指标范围和未决计划明确。

## 汇报的首轮写回问题

首次输出四个内容段落，但用双换行分隔，实际成为七个原生段落。应用提示“修订改变了段落结构，无法确认原生格式保真”，未覆盖Notes。此保护是有效的，但模型生成与原生格式之间仍有一次交互成本。

后续给同一真实模型追加：

> 仅修正上一稿的换行格式：正文恰好4行，用单个换行分隔，不插入空白行；不要改变上一稿的事实和处理结果。

复核程序确认第二稿等于第一稿移除段间多余空行，五条批注未变。没有手工改写模型正文。第二次写回及一次撤销通过。

## 后续改进判断

- 公众号与个人笔记：进一步强化不同读者目标和组织策略，在更多题材上做同输入对照；本轮没有擅自改动用户角色配置或只挑好看的结果。
- 原生段落保真：生成端应更明确地传递单换行结构约束，或在应用前明确处理纯空行差异；当前保守拒绝覆盖有效。
