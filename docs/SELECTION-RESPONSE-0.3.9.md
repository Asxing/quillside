# 0.3.9 段落拖选响应修复与验证

2026-10-09。用户反馈：双击一个词时快，鼠标拖选一段话后有时等待半秒到一秒，表现不稳定。

## 诊断证据

旧实现收到选区事件后经过16ms debounce，再在窗口发现共用队列读取选区位置和整段富文本格式，全部完成才显示工具条。拖选中连续事件会等待静默，同时新一轮generation会让旧查询结果作废；双击选词通常没有这种持续变化。

临时计时只记录毫秒数，不记录笔记内容。短选区从查询开始到orderFront约12–16ms，三千多字选区约34–37ms，其中格式读取约23–28ms。一次可归因到鼠标松开的5次短选区样本约35–47ms。跨行拖选通过CUA产生的事件有缺失/旧时间戳，不能用它虚构半秒延迟已被稳定复现或已缩短到某个数字；其异常计时已排除。

以上确认了不必要的串行等待和事件处理风险，但尚未把用户的间歇性0.5–1秒尾延迟唯一归因到某一个阶段。后续已安装并由用户真实连续拖选验收，结果见下文。

## 已实现的修复

- 鼠标按下开始选择时取消旧请求，拖动期间不重复查询；鼠标松开立即刷新，必要时仅在35/90ms各补一次，未引入持续轮询。
- 选区事件由debounce改为throttle，连续通知不再无限等待静默。
- 选区定位使用独立userInteractive队列，不与全窗口发现共用队列。
- 选区位置可用即显示；格式状态在另一队列异步补充。慢格式查询不能阻止新选区工具条显示。
- 关闭NSPanel出现动画，减少视觉等待；切应用/取消后丢弃过期结果。
- 格式状态读取超过16,384 UTF-16单元时跳过，以避免Notes序列化超大富文本。工具仍对真实完整选区操作，只是不显示未证实的格式勾选。
- AI定位只取geometry，不再为了定位顺带读取全部格式。

## 回归

196项测试中195执行通过、1项旧宣传截图跳过，31套件。新增生产SelectionSnapshotReader回归：格式查询挂起时geometry先交付，新选区不被旧格式阻挡，1000次事件只保留最新待处理请求，取消后结果不能重弹。源码临时计时插桩已移除，Release和严格签名验证通过。

## 安装后验证

已解除锁屏并安装0.3.9，Applications版本、二进制指纹与构建包一致。AX/FDA记录继续匹配，无需重新授权。临时计时插桩已清理。

真实Notes中完成：短选区、多行完整段落、另一行选区三轮切换均显示工具条，取消后收起；Shift+Down扩选两行后工具条出现，多行加粗及原生撤销成功；读回原合成笔记内容完整。

自动化跨三行拖选第一轮显示/收起成功，但第二轮触发Notes退出。为排除增强器影响，正常退出AppleNotesPro并用pgrep确认无进程后，再执行同一CUA拖选路径；同样在第二轮让Notes退出。崩溃栈为Notes/AppKit的NSSelectionArray、setSelectedRanges、_bellerophonTrackMouse、mouseDown。已停止这条不稳定的自动化输入路径并恢复Notes；不能把自动化崩溃当作增强器导致，也不能据此声称真实鼠标尾延迟已量化解决。

用户随后手动连续拖选确认：“明显更快，连续拖选也稳定”。该问题的真实鼠标验收通过。此结论是用户实际体验确认，不是自动化量出的精确毫秒值。程序保持运行，用户可以直接使用新版。没有向模型发送笔记，没有修改原模型配置或密钥。
