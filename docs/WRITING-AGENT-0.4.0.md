## 使用

1. 设置 → 写作 Skills，启用 humanizer-zh，或导入包含 SKILL.md 的文件夹。本轮内置中文技能已启用。
2. 在Notes选择要修改的连续文字；不选择文字时以当前笔记为修订范围。打开AI小浮层，点击“批注修订”。快捷润色仍可直接使用。
3. 左侧候选稿中选一句话，在右侧输入修改意见，点击“添加批注”。可以连续标十处，每版最多50条、任务总计最多200条。
4. 可开启/关闭“参考当前笔记全文”，填写整体要求，点击“统一优化”。写作内核先分析，再形成整体稿，再核对遗漏、事实和前后逻辑；核对失败时最多修正一次。
5. 每条意见有处理说明。旧版本批注继续作为后续轮次的约束；旧范围不会错误画到新文本。可以编辑、停用、删除意见，或从历史恢复对应稿件。候选稿可手动编辑，旧批注保留，但不猜测新位置。
6. “保存并返回Notes”保留草稿，退出/重启后在同一笔记重新进入可恢复。也可回Notes选择另一处，进入会话后点击“加入Notes选区”；只有候选稿唯一匹配该引用时才定位。
7. 先预览，确认后替换原选区或插入后方。Notes正文已变化时停止写入。一次原生粘贴对应一次Undo，实机已验证。

“从当前选区新建”明确开启新的任务，先把旧草稿归档，不静默覆盖原任务。

## 内核与Skill实现

WritingAgent是有界写作Agent：plan → 模型请求已提供的Skill文本资源 → revise → audit → 可选repair。最多四次模型调用，模型不能直接写Notes或执行脚本。四种既有模型协议通过结构化JSON文本承载这一应用级流程；本版不是通用shell Agent，也不声称实现每个服务商专有tool-calling接口。

请求包含原文、当前候选、全部启用批注、最近候选历史、总体要求、启用的Skill指令；全文上下文由显式开关决定。输出的批注ID必须完整且不重复，每条状态只能是addressed/conflict/unresolved；JSON无效、遗漏批注、输出截断、取消或资源越界时保留上一稿，不应用Notes。

标准Skill加载用Yams 6.0.2解析YAML头，支持字符串/数组allowed-tools、块标量、Markdown正文和references/assets文本资源。导入时固定包内容摘要，运行中不扫描Skill文件夹；模型按需请求已快照资源。单文件128KiB、包文本512KiB、配置总量4MB；真实路径限制在所选目录，不允许符号链接逃逸。模型任务最多启用8个Skill。

内置[Humanizer-zh](https://github.com/op7418/Humanizer-zh)固定提交f4518a8eab97b8bfebc66a89d34320a89bef6930，保留原SKILL.md、MIT许可与来源文件。支持其写作指令，不执行任意外部脚本或宿主专属工具。兼容范围在设置可见。导入Skill不需要安装Node/Python运行时。

原快捷AI的“继续修改”现在基于上一候选（包括用户手改结果）和最近四轮要求继续，不再总回到最初原文。复杂任务使用修订会话保存历史，二者入口共享已有Notes保护性写回。

## 明确边界

- 本版实际划线/评论位于应用自己的原生候选稿。Notes原文可选句加入意见，但不在第三方Notes编辑器上持续绘制跨行批注层。
- 替换必须能从Notes取得该范围完整RTF且原文匹配；本版保留未变段落的富文本，改变的段落继承原段落基本格式。段落数量变化、附件/表格对象或RTF不可读取时拒绝覆盖，保留“插入后方/复制”选项。不是任意复杂文档的无损重写。
- 逻辑自洽由共同上下文、逐条核对及人工审阅提高质量，不能保证模型每次都正确；冲突和未解决意见会显式保留。
- 每个笔记一个当前草稿，最多12个全文历史版本；用户批注要求不随旧全文版本裁剪而悄悄删除。草稿按需保存本机，不同步到其他设备，不建立检索索引。
- 开启多个窗口、切换应用时不允许旧结果直接写入新目标。正文改变后保留旧草稿，需要重新建立当前范围的任务。
